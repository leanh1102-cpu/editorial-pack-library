# Chapter / Arc Rhythm — Source-Grounded Structural Judgment v0.1

**Status:** `CANDIDATE / TDD TARGETED GREEN / HOLDOUT PENDING`

## CONCEPT

Chapter/arc rhythm is the pattern of **state change, pressure modulation, causal preparation, consequence, and scene-function variation across ordered scenes**.

Do not equate rhythm with constant intensity. Do not diagnose a quiet scene as weak merely because external action is low.

Core question:

`WHAT CHANGES → HOW DOES PRESSURE CHANGE → WHAT MECHANISM MOVES THE SCENE → WHAT COST/CHOICE SURVIVES → WHAT DOES THE NEXT SCENE INHERIT?`

## SCOPE

Use this module when the task concerns:
- several ordered scenes;
- a whole chapter or chapter packet;
- arc pacing or escalation;
- repeated scene mechanisms;
- climax preparation or repeated payoff type;
- missing aftermath;
- seam/transition saturation;
- chapters that feel flat although individual scenes are competent.

Do not use this module to impose a universal story shape or beat count.

## STRUCTURAL MAP

For each relevant scene, record only what is materially supported:

`SCENE FUNCTION / PRESSURE TYPE / STATE CHANGE / COST OR CLOSED OPTION / RELATION OR OBJECT CHANGE / SEAM / INHERITED CONSEQUENCE`

A scene may earn its place through:
- decision;
- changed access;
- changed relation;
- changed object/resource state;
- new evidence or reinterpretation;
- consequence/aftermath;
- preparation that later becomes causally necessary;
- recovery that changes what characters can do together;
- useful compression or orientation.

A scene does **not** need a climax.

## DIAGNOSTICS

### 1. Pressure plateau
A plateau exists when several consecutive scenes revisit the same unresolved question or pressure without materially changing:
- amount;
- deadline;
- access;
- option;
- plan;
- evidence;
- cost;
- relation;
- object/resource state;
- interpretation;
- decision.

Competent prose does not rescue redundant scene function.

### 2. Repeated scene mechanism
Surface variation is not functional variation.

Example pattern:
`ARRIVE → ASK → RECEIVE INFORMATION → LEAVE`

Different speakers and locations may still produce repetition if the protagonist repeatedly acquires information through the same frictionless mechanism.

Diagnose the mechanism before suggesting variation.

### 3. False escalation
Louder language, harsher insults, more fragments, public exposure, or more dramatic phrasing do not by themselves create escalation.

Escalation requires an evidence-supported change in:
`COST / ACCESS / OPTIONS / DEADLINE / RELATION / ASSET / KNOWLEDGE / COMMITMENT`

### 4. Repeated payoff mechanism
Different conflicts can still feel repetitive if every major climax converts pressure through the same decisive mechanism, such as:
- winning by the strongest public speech;
- being rescued by a last-minute arrival;
- discovering a hidden document;
- defeating an opponent through the same type of action.

The diagnosis is **payoff-mechanism repetition**, not “this type of scene is bad.”

### 5. Missing aftermath
A climax creates debt when it establishes injury, rupture, loss, exposure, obligation, guilt-relevant choice, changed access, or object/resource damage.

The next chapter need not become slow, but it must not silently reset those established consequences.

### 6. Seam saturation
Any transition method can become repetitive when repeated across many scenes:
- departure through a door;
- isolated punch-line sentence;
- sleep/waking;
- “later that day”;
- phone/message arrival;
- reflective maxim.

Keep locally functional seams. Repair the **saturation pattern**, not the existence of the device.

### 7. Useful low-intensity chapter
Preserve a quiet chapter when it materially changes preparation, relationship, object state, resource allocation, interpretation, recovery, or future capacity.

Low intensity is not a failure category.

## SOURCE-GROUNDED INTERVENTION LADDER

When a multi-scene problem is found, use this order.

### STEP 1 — PRESERVE if the packet already has functional variation
Do not make pressure monotonic. Do not add excitement solely for variety.

### STEP 2 — COMPRESS / MERGE / REMOVE redundant nodes
If several scenes perform the same job and no new state change occurs, first ask:
- Can two scenes become one?
- Can one warning/information beat be removed?
- Can a repeated exchange be summarized?
- Can a redundant scene function disappear without continuity loss?

This is the default response to unsupported repetition.

### STEP 3 — REDISTRIBUTE ALREADY-ESTABLISHED MATERIAL
Before inventing anything, inspect the packet for existing:
- costs;
- obligations;
- access limits;
- objects/resources;
- relationship tensions;
- evidence;
- choices;
- deadlines;
- consequences.

Move or reveal that established material at a better scene node when causally legitimate.

### STEP 4 — REASSIGN FUNCTION TO A SURVIVING SCENE
A redundant scene can donate its only necessary information or consequence to a neighboring scene that already has a stronger function.

Do not preserve a whole scene merely to carry one repeated warning.

### STEP 5 — VARY MECHANISM ONLY WHEN SOURCE SUPPORTS IT
If the source already establishes bargaining leverage, concealment, failed access, object work, competing obligation, sacrifice, resource loss, or another mechanism, it may be redistributed or foregrounded.

**Do not invent one merely because the chapter needs variation.**

If the packet contains no supported new mechanism that can create the desired structural change:
- do **not** invent one;
- if compression, merge, removal, reweighting, reassignment, or redistribution of existing material can still repair the multi-scene pattern, choose bounded `REVISE`;
- use `HOLD-INSUFFICIENT_EVIDENCE` only for the unsupported **new event/mechanism itself**, or for the whole task when no evidence-grounded structural repair remains.

## CLIMAX VARIATION RULE

When major payoffs repeat:
1. identify the repeated payoff mechanism;
2. inspect already-established costs, actions, obligations, relationships, access limits, and object states;
3. ask whether one climax can convert pressure through one of those **existing** mechanisms;
4. if the packet does not supply such material, do not manufacture a sacrifice, betrayal, attack, deadline, clue, romance beat, or loss merely to diversify the climax.

A recommendation such as “add a sacrifice” or “make them lose access” is unsupported unless that possibility already exists in source evidence.

If the repeated payoff type is real but the packet does not expose a supported replacement mechanism, do not HOLD the whole revision automatically. First consider bounded `REVISE` by compressing, merging, de-emphasizing, reweighting, or reassigning repeated payoff nodes so the arc stops presenting the same mechanism as the decisive resolution every time. HOLD only the request to invent a replacement mechanism that the source does not support.

## AFTERMATH RULE

Aftermath does not require a fixed scene length.

Restore established consequence at the smallest structural location that prevents false reset:
- a changed behavior;
- a missing person;
- an object/resource consequence;
- a relationship avoidance;
- a practical restriction;
- a brief recovery exchange;
- a carried obligation.

Do not invent emotional certainty. Preserve ambiguity where the source preserves it.

## ACTION SCALE

Use `MIN_EDIT` only when the repair is genuinely local to a sentence, phrase, or one narrow transition.

Use `REVISE` when the required intervention spans:
- multiple turns;
- multiple paragraphs;
- more than one scene;
- scene merging/deletion/reassignment;
- compression or reweighting of repeated scene/payoff nodes;
- chapter-boundary aftermath;
- repeated seam mechanisms;
- repeated climax/payoff mechanisms.

A task remains `REVISE` when a valid source-grounded structural repair exists, even if one *particular* proposed new mechanism must be rejected for insufficient evidence.

`REVISE` does not mean rewrite the whole chapter. It may be a bounded two-scene restructuring.

## ANTI-OVERREACH

Do not:
- require a fixed number of climaxes, quiet beats, or aftermath scenes;
- demand monotonic pressure increase;
- prescribe “add action / fight / twist” generically;
- invent new canon to cure rhythm;
- change every seam because several seams repeat;
- remove a quiet preparation/recovery scene that changes state;
- call different locations/characters sufficient scene variation when the mechanism is identical;
- treat prose intensity as structural escalation;
- diversify climax type by manufacturing unsupported sacrifices, deadlines, betrayals, access losses, clues, or accidents.

## OPERATIONAL SEQUENCE

`MAP ORDERED SCENES`
→ `NAME EACH SCENE'S FUNCTION`
→ `TRACK STATE/PRESSURE CHANGE`
→ `FIND PLATEAU OR MECHANISM REPETITION`
→ `CHECK CLIMAX PREPARATION / PAYOFF TYPE / AFTERMATH / SEAMS`
→ `SEARCH EXISTING SOURCE FOR USABLE COST/CHOICE/ACCESS/OBJECT/RELATION`
→ `CHOOSE SMALLEST SOURCE-GROUNDED STRUCTURAL INTERVENTION`
→ `REGRESSION CHECK`
→ `STOP`

## REGRESSION CHECK

Before finalizing a recommendation, ask:
- Am I fixing a multi-scene pattern rather than disliking one scene?
- Did I preserve useful irregularity and recovery?
- Did I propose a new mechanism the packet never established?
- Could compression/merge/reassignment solve this without new canon?
- Did I protect existing aftermath debt?
- Did I convert a repeated pattern into a quota or ban?
- Is my action scale local enough but large enough?

## STOP CONDITION

Stop when:
- every surviving scene has a defensible function or inherited consequence;
- no material plateau/repetition remains;
- additional variation would require unsupported canon;
- the next proposed change is preference rather than evidence-backed structural repair.
