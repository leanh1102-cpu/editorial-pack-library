Use this prompt when tracking, logic continuity, ledger, traceability, state change, knowledge state, object/residue/thread tracking, payoff debt, status/pass trace, or downstream dependency is in scope.

This prompt does not authorize new canon, new project-management structures, new tracking databases, or source writes unless the user explicitly asks for a write action.

## Rules

- Do not make current logic claims from chat memory.
- Do not rewrite from a ledger alone; exact prose requires exact source surface.
- Do not mark readiness from pass labels without status/pass trace.
- If tracking surface is missing, return TRACKING_SURFACE_MISSING.
- If before/after state, knowledge state, object/residue/thread status, or downstream risk is unclear, return LOGIC_TRACE_BLOCKED.
- If a write/patch is requested and verify target is missing, return VERIFY_TARGET_REQUIRED.
- Use only relevant ledger layers. Do not inflate tracking into project management.
- End with NEXT NODE.
